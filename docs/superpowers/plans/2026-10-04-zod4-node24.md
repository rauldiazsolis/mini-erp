# Zod 4 y @types/node 24: plan de implementación

> **Para agentes:** se ejecuta con `superpowers:executing-plans`, **tarea por tarea en la misma
> conversación** (AGENTS.md: nunca un subagente por tarea). Al terminar cada tarea, verificar y frenar
> para que el usuario la revise. Los pasos usan casillas (`- [ ]`).

**Objetivo:** pasar a `zod ^4.6.5` y `@types/node ^24.19.1` sin cambiar comportamiento, salvo los
mensajes por defecto de Zod, que pasan a estar en castellano.

**Arquitectura:** `src/shared/zod.ts` configura `z.locales.es()` y reexporta `z`. Todo `src/` y
`scripts/` importa de ahí (lo hace cumplir el lint). La API de Zod 3 se traduce a la de Zod 4 conservando
cada texto propio, y antes de migrar se fijan con tests.

**Stack:** Zod 4, TypeScript 6 (strict, `exactOptionalPropertyTypes`), Vitest, ESLint
(`strictTypeChecked`, con `no-deprecated`), Node 24.

**Spec:** `docs/superpowers/specs/2026-10-04-zod4-node24-design.md`

## Restricciones globales

- Rama `claude/zod4-node24`. Commits convencionales en español, con
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- pnpm se corre desde PowerShell.
- Antes de cada commit: `pnpm lint; if ($?) { pnpm typecheck }; if ($?) { pnpm test }` en verde.
- Ningún texto de error propio cambia. Lo único que cambia son los mensajes por defecto de Zod.
- Un evento inválido del push nunca rechaza el lote: `200` y un `issue`.
- No se usa `as` ni `!` para callar errores de tipos.
- La versión pasa a `0.11.2`.
